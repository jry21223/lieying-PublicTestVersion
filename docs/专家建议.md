# 「猎影」开发专家建议

> 作者：25年+经验的安全开发专家

## 一、架构设计原则

### 1.1 本地优先（Offline First）
**设计理念**：
- 默认完全离线运行，不依赖任何外部服务
- 需要联网时才"出网"，且必须经过用户明确授权
- 所有核心POC库、漏洞库、工具链都内置在本地

**实现要点**：
```yaml
# configs/config.yaml 中的默认配置
network:
  mode: offline              # 默认为离线模式
  proxy:
    enabled: false
```

### 1.2 可控出网（Controlled Egress）
**三层网络控制**：
1. **应用层控制** - NetworkManager 统一管理所有HTTP请求
2. **主机白名单** - 只允许访问配置的主机
3. **代理强制** - 需要联网时强制走用户配置的代理

**网络流程**：
```
用户请求 → NetworkManager检查 → 
  ├─ 离线模式 → 拦截并报错
  ├─ 代理模式 → 走用户配置的代理
  └─ 直连模式 → 检查白名单后直连
```

## 二、开发路线图（按优先级）

### 第一阶段：本地核心（1-2个月）
**优先级：P0**

- [ ] **CLI工具框架** - 可用的命令行工具入口
- [ ] **本地POC库** - 内置1000+常用POC（Nuclei格式）
- [ ] **基础扫描引擎** - 集成Nuclei本地扫描
- [ ] **信息收集工具** - 子域枚举、端口扫描（纯Go实现，可选出网）
- [ ] **报告生成器** - 本地生成SRC规范报告

**技术要点**：
- 所有工具用Go重写，不依赖外部二进制
- POC库打包进二进制，或者作为资源文件
- 扫描结果存在本地SQLite（不依赖PostgreSQL）

### 第二阶段：AI本地化（2-3个月）
**优先级：P0**

- [ ] **Ollama深度集成** - 一键拉起本地Ollama
- [ ] **本地微调模型** - 提供安全专用的微调版Qwen
- [ ] **AI推理加速** - GGUF格式，4-bit量化，CPU也能跑
- [ ] **Prompt模板库** - 内置POC生成、报告生成的专业Prompt

**推荐模型**：
- 入门：Qwen2.5:7B (GGUF, 4-bit) - 4GB内存可用
- 进阶：Qwen2.5:14B (GGUF, 4-bit) - 8GB内存可用
- 专家：Qwen2.5:32B (GGUF, 4-bit) - 16GB内存可用

### 第三阶段：高级功能（3-6个月）
**优先级：P1**

- [ ] **浏览器指纹模拟** - 纯Go实现，不依赖Chromium
- [ ] **WAF绕过规则库** - 内置Payload变异引擎
- [ ] **业务逻辑测试** - 越权、支付绕过等自动测试
- [ ] **教育SRC专属** - 高校域名库、教务系统POC

### 第四阶段：可选联网（6个月+）
**优先级：P2**

- [ ] **POC市场同步** - 可选联网更新POC库
- [ ] **漏洞情报订阅** - 可选接收最新CVE情报
- [ ] **社区功能** - 可选分享POC（需用户授权）

## 三、关键技术决策

### 3.1 Go vs Java 职责划分
| 组件 | 语言 | 原因 |
|------|------|------|
| 扫描引擎 | Go | 高性能、并发强、静态链接单文件 |
| 信息收集 | Go | 原生网络库强、跨平台 |
| CLI工具 | Go | 单文件分发、启动快 |
| Web控制台 | Java | Spring生态成熟、快速开发 |
| AI服务 | Go/Java | 都可以，建议Go简化部署 |

**建议**：先做Go的CLI和引擎，Java Web控制台后期再加。

### 3.2 数据库选择
- **开发/单机**：SQLite - 零依赖、单文件
- **企业/集群**：PostgreSQL - 可选项

### 3.3 打包分发
- **Windows**：.exe单文件 + 资源文件夹
- **Linux**：.deb/.rpm + AppImage
- **macOS**：.dmg + Homebrew

## 四、安全设计（非常重要）

### 4.1 自保护机制
- 工具自身检测是否在虚拟机/沙箱运行
- 检测调试器附加
- 代码混淆（可选，防止逆向）

### 4.2 防止滥用
- 每个任务前弹出确认对话框
- 记录所有操作日志（本地）
- 可选配置"目标白名单"

### 4.3 法律合规
- 启动时显示法律声明
- 用户必须同意才能使用
- 内置"仅用于授权测试"的水印

## 六、避免的坑（25年经验总结）

### ❌ 不要做的
- 不要一开始就做Web UI - 先把CLI做扎实
- 不要依赖外部服务 - 默认必须离线可用
- 不要过度设计 - 先实现最小可用产品
- 不要用太多依赖 - 保持Go.mod简洁

### ✅ 要做的
- 频繁发布小版本 - 快速迭代
- 收集用户反馈 - 白帽需要什么就做什么
- 编写详细文档 - 工具再好，不会用也白搭
- 建立社区 - POCO库需要社区贡献
